# PROJECT
Mediator landing page

# STACK
React
TypeScript
Vite
SCSS

# BRAND
Название бренда: «Медиатор».

Сайт принадлежит агентству. Это не личный сайт Любови Кузнецовой. Любовь Кузнецова может быть представлена как руководитель или специалист агентства, но бренд «Медиатор» всегда должен оставаться главным.

# DESIGN DIRECTION
Главный визуальный reference предоставлен: единый макет для desktop (1440px), tablet (768px) и mobile (375px). Сверяться с ним при реализации. Старый Tilda-сайт — только вторичный источник; контакты и устаревший текст с него не переносить без подтверждения.

Направление: теплый кремовый фон, мягкие бежевые оттенки, терракотовый акцент, темный коричневый или почти черный текст, свободное пространство, editorial типографика, крупные serif-заголовки и sans-serif интерфейс, тонкие границы, минимальные тени, умеренные скругления и спокойный premium legal стиль.

Избегать вида AI-шаблона, конструктора, инфобизнеса, личного блога, сайта одного юриста, банковского корпоративного сайта или SaaS dashboard.

# CONTENT
Основное направление: банкротство физических лиц.

Подтвержденные формулировки: процедура под ключ; свои арбитражные управляющие; мировые соглашения; банкротство в рассрочку. Агентство работает с физическими и юридическими лицами. Новые услуги согласовывать до добавления.

# FACT SAFETY
Не выдумывать стоимость, число клиентов, процент успешных дел, срок работы компании, адрес, телефон, email, гарантии, количество процедур или рейтинги. Не использовать неподтвержденные обещания вроде «98% успешных дел», «500+ клиентов», «гарантированное списание долгов», «спишем 100% долгов» или «лучшие юристы Екатеринбурга». Недостающие сведения помечать TODO в data-файлах.

# LEGAL COPY
Не обещать юридический результат. Использовать нейтральные формулировки: «помогаем пройти процедуру», «сопровождаем», «анализируем ситуацию», «предлагаем законные варианты решения», «оцениваем перспективы».

# RESPONSIVE
Проектировать для desktop, tablet и mobile. Использовать flex, grid, clamp(), min(), max() и media queries. Не строить основную сетку на абсолютном позиционировании.

# COMPONENTS
Каждая крупная секция — отдельный небольшой и понятный React-компонент. Не дробить интерфейс без причины. Повторяющийся контент хранить в `src/data`, а не в больших JSX-массивах.

# STYLING
Использовать SCSS Modules либо организованную SCSS-архитектуру последовательно. Не использовать inline styles без необходимости. Повторно используемые значения задавать CSS/SCSS переменными: фон, поверхность, акцент и hover, основной и вторичный текст, границы, ширина контейнера, радиус и вертикальные отступы секций.

# ACCESSIBILITY
Использовать семантические `header`, `nav`, `main`, `section`, `footer`; alt для изображений; `button` и `a` для интерактивных элементов; label или aria-атрибуты у форм; видимые focus states. Не убирать outline без замены.

# IMAGES AND ICONS
Не использовать случайные stock/Unsplash assets. Временные фотографии, подготовленные для текущей реализации по предоставленному визуальному reference, хранить отдельными replaceable assets и явно помечать как временные; заменить реальными материалами агентства до публикации. Не использовать текст, кнопки или layout, вшитые в изображения. Для стандартных UI-иконок использовать lucide-react; фирменную графику брать из предоставленных оригинальных assets, не рисовать логотип самостоятельно.

# DESIGN WORKFLOW
Реализовать лендинг по предоставленному визуальному mockup. Использовать Product Design user-context и get-context перед image-to-code, затем проверять визуальную верность через design-qa. Figma не создавать без необходимости.

# SCOPE
До отдельного запроса не начинать полноценную верстку, не создавать страницы, backend, CMS, аналитику, отправку форм или deployment. Сохранять простую production-ready frontend архитектуру.
